# 006 - 产品整体重设计（入口 / 交互 / UI 流程）需求规格

## 产品定位

把 App 从「闹钟规则管理器」重设计为「我的节奏」：核心能力仍是 **每隔 N 天提醒一次**（排班、浇花、定期任务），但产品叙事围绕「现在和下一次会发生什么」组织，而不是围绕「我配置了哪些规则」。本次重设计覆盖入口、信息架构、交互流程和视觉体系，同时**完整保留** 001~005 已交付的全部能力，不删功能、不改数据模型和调度逻辑。

## 需求背景

当前 App 是五个 spec 功能叠加的结果：首屏是带搜索、双筛选、排序的规则列表；创建页用四个并列类型选项 + 六个表单卡片；日历、设置各自为政。功能齐全但属于「堆砌」：

- 首屏回答的是「我设了哪些闹钟」，不是用户每天真正关心的「今天接下来有什么、下一次是什么」。
- 产品的灵魂「X 天周期」在 UI 上只是四个类型选项之一，没有节奏感的表达。
- 创建流程按数据库字段组织表单，而不是按用户心智组织问题。
- 各页面视觉层级、入口语义不一致，附加功能（搜索/筛选/排序/冲突/复制）与主流程平铺在同一层。

## 设计原则

1. **节奏优先**：任何页面先回答「什么时候响」，再回答「规则是什么」。周期闹钟要能表达「进行到第几天、还有几天」。
2. **主线收敛**：创建流程围绕一条主线「这个提醒多久响一次」，一次/每天/每周作为周期模型的自然特例，而非并列选项。
3. **层级分级**：高频看（今日/下一次）、中频看（计划分布）、低频管理（全部列表、设置）。功能不删，但按使用频率下沉。
4. **兼容不动核心**：数据模型（alarms / alarm_adjustments / settings）、调度计算（scheduler）、通知调度策略零改动；重构只发生在 UI 层、路由层和展示组件层。

## 信息架构（一级导航）

底部固定 4 Tab，职责如下：

| Tab | 定位 | 回答的问题 | 使用频率 |
|---|---|---|---|
| 今日 | 看当下 | 今天接下来有什么会响？下一次是什么、还有多久？ | 每天 |
| 计划 | 看全局 | 未来一段时间提醒如何分布？某天有什么？ | 每周 |
| 全部 | 管理 | 我设了哪些提醒？怎么找到并调整某一条？ | 低频 |
| 设置 | 配置 | 权限、默认值、外观 | 极低频 |

- 创建/编辑是 Tab 外层子页面（`app/create`、`app/[id]/edit` 结构保留），进入时隐藏 Tab，返回后回到原 Tab 上下文。
- 「今日」为默认启动页。
- Tab 图标首版继续用字体符号，视觉阶段替换。

## 页面功能详述

### 1. 今日 Tab（新首屏）

**顶部：日期与问候区**

- 显示今天日期（如「10月3日 周六」）和一句话状态（如「今天有 3 个提醒」/「今天没有提醒，下一个在 2 天后」）。

**核心区：「下一次响铃」主卡片**

- 全屏最醒目的一张卡，展示距离现在最近的未来提醒：
  - 时间（大字号）+ 标签 + 分类色标识
  - 距离现在的倒计时（「还有 2 小时 15 分」/「还有 2 天」）
  - 周期闹钟额外显示节奏信息：「4 天周期 · 今天第 2 天 · 还有 2 天响」
- 点击进入该提醒编辑页。

**次要区：今日时间轴**

- 今天剩余会响的提醒，按时间升序排列的紧凑列表（时间 + 标签 + 分类色条）。
- 已响过的排在末尾并置灰（一次性提醒显示完成态）。
- 今天没有提醒时显示空状态 + 「下一个在 X 天后」的引导。
- 点击条目进入编辑页；左滑提供「跳过一次」（周期）。

**快捷新建**

- 右下角 FAB「＋新建」，所有 Tab 统一。

### 2. 计划 Tab（日历）

- 保留 003 的全部能力：月 / 周 / 3天 / 日四视图、前后翻页、「今天」、分类色标识、暂停提醒筛选、点击实例进编辑。
- 顶部重组为两层：第一层是日期范围与翻页，第二层是视图切换分段控件；去掉装饰性大标题。
- 月视图保留分布密度（数量点/色条）；周期提醒在月格上体现「跳过」的样式区分。
- 空状态：没有任何提醒实例时引导去「全部」Tab 创建。

### 3. 全部 Tab（管理列表，现有列表页重组）

- **默认视图**：按「下次响铃时间」升序的提醒卡片列表；已暂停的沉到列表底部。卡片显示时间、标签、重复规则、下次响铃日期、开关。
- **搜索与筛选收纳**：搜索框 + 筛选/排序不再平铺占两屏，收进列表头部一个可展开的「筛选」行（点开后出现搜索、类型筛选、分类筛选、排序选项），记住上次状态。
- **卡片操作**：点击进编辑；周期闹钟保留跳过一次 / 临时加一次 / 复制 / 删除操作（保留现有交互方式，按视觉阶段确定是左滑还是更多菜单）。
- **空状态**：与今日 Tab 联动的引导文案 + 创建按钮。
- 保留「查看日历」语义：列表头部提供去计划 Tab 的快捷入口，行为等价于切 Tab，不产生新导航栈。

### 4. 设置 Tab

- 保留 005 全部能力：通知权限（状态展示 / 申请 / 跳系统设置）、默认稍后提醒时长、主题（浅色 / 跟随系统）。
- 视觉随新主题 Token 重做，功能不变。

### 5. 创建 / 编辑流程（重新设计）

核心变化：**用一条主线取代四选项 + 平铺表单**。

**主线：「这个提醒多久响一次？」**

- 第一步（时间 + 频率合一的主界面）：
  - 顶部：时间选择（保留现有 TimePicker，视觉重做）。
  - 中部：频率选择器，选项重新表述为用户语言：
    - 「就一次」
    - 「每天」
    - 「每周选几天」（选中后展开星期选择）
    - 「每 N 天一次」（选中后展开起始日期 + 间隔天数，并提供「从明天开始 / 从今天开始」快捷项）
  - 「每 N 天」是本产品的差异化能力：主次区隔只通过默认选中、选项顺序和展开层级表达（创建页默认选中「每 N 天」），**不向用户展示「核心」「主打」类标签**。
- 第二步（可选信息，弱化）：标签、分类、稍后提醒时长收进「更多选项」折叠区或页面下部低权重区，全部有默认值，可不填直接保存。
- 保存前的冲突检测（004）保留：静默检测，仅发现冲突时弹确认。
- 编辑页复用同一套表单组件（create 与 edit 组件级复用，消除当前两份 370 行的重复实现）。

**交互细节要求**

- 每个频率选项选中后仅展开自己需要的字段，切换频率时自动清空不相关字段（与现有数据模型 nullable 字段对应）。
- 表单一屏内完成，不引入多步向导。

## 视觉范围

- 视觉方向已选定：**沿用现有 Eva / UI Kitten 浅色 token**（002 已确认方向，`src/constants/index.ts` 的 COLORS 为单一来源），本次不换视觉。
- 允许在现有 token 体系内小幅补充缺失 token（如「下一次响铃」hero 卡的 primarySoft 底 + 深紫字、节奏点阵用色），不引入新风格。
- 约束不变：视觉服从「节奏优先」的信息层级——时间与倒计时是第一层级，规则描述第二层级，管理操作第三层级。

## 现有功能保留清单（重构验收红线）

以下能力重构后必须全部可用，属验收一票否决项：

1. 四种闹钟类型的创建、编辑、删除、开关（001）
2. 周期闹钟的偏移起始日、修改间隔、跳过一次、临时加一次（001）
3. 周期闹钟正确按 N 天循环触发通知（001，调度逻辑零改动）
4. 通知与稍后提醒（含通知操作按钮、点击通知打开 App）（001）
5. 日历月/周/3天/日四视图与实例点击编辑（003）
6. 搜索、类型/分类筛选、排序（004，收纳但保留）
7. 提醒冲突检测（004，保存时静默触发）
8. 复制闹钟（004）
9. 设置：通知权限、默认稍后提醒、主题（005）
10. 现有全部单测（scheduler / calendar / conflicts / date）继续通过

## 数据与兼容性

- **不新增、不修改**任何数据库表和字段；不修改 `src/services/scheduler.ts`、`src/db/` 的行为语义。
- 已有用户数据在升级后无损可见。
- 代码层面的重构目标（组件化、分页面、去重 create/edit 表单）在 design.md 中确定具体结构，并沉淀为项目知识中的「代码结构说明」。

## 非功能需求

- 页面切换不白屏，Tab 状态保留策略沿用 005（列表/日历状态本会话保留，设置跨重启）。
- 今日 Tab 的「下一次响铃」计算复用现有 `computeNextRingDate`，不新写一套日期规则。
- 所有新组件 TypeScript strict，无 any。
- 视觉 Token 单一来源，禁止页面内散落硬编码颜色（白色文本等例外需收敛进 Token）。

## 不在本需求范围内

- 不新增闹钟类型、不改调度规则、不做云同步/导入导出（004 P2 项仍搁置）。
- 不做完整深色主题（Token 体系预留，视觉阶段决定是否首版包含）。
- 不更换通知实现方式（全屏响铃、自定义铃声仍是后续升级）。
- 不做桌面端/平板专门布局。

## 验收标准

1. 启动进入「今日」Tab：能一次看清今天会响的提醒、下一次响铃（含倒计时）与周期节奏信息。
2. 底部 4 Tab 可用且选中态清晰，创建/编辑页隐藏 Tab，返回后回到原 Tab 上下文。
3. 创建流程以「多久响一次」为主线，「每 N 天」可直达且有明确主次层级；四种类型均能正常创建并正确调度。
4. 「全部」Tab 搜索/筛选/排序全部可用但默认不占首屏；卡片操作（跳过/加一次/复制/删除）可用。
5. 「计划」Tab 四视图及翻页、今天回位、暂停筛选、实例点击编辑全部可用。
6. 设置 Tab 三组设置项功能与 005 验收一致。
7. 现有单测全部通过；tsc strict 零错误；Android dev 构建装机后核心流程（创建周期闹钟→到点通知→稍后提醒）人工验证通过。
8. 旧数据（升级前创建的闹钟）在新 UI 下完整可见、可编辑、调度不变。

## 已确认决策

- 术语：用户可见文案统一用「稍后提醒」取代「贪睡」（产品叙事是节奏提醒，不是闹钟叫醒）；代码标识符、数据库字段、通知 action 内部值沿用 `snooze` 不改，仅改展示层文案。

- 首屏入口：「今日/下一次」视角（用户确认按设计思路执行）。
- 一级导航：4 Tab —— 今日 / 计划 / 全部 / 设置（用户确认按设计思路执行）。
- 附加功能：全保留，按信息层级重组收纳，不删减。
- 视觉：**沿用现有 Eva / UI Kitten 浅色 token（方案 0 基线）**，只重组信息架构与交互流程，不换视觉（2026-10-03 确认）。
- 产品叙事：从「闹钟管理」转为「我的节奏」，周期提醒是第一公民。
- 数据与调度层零改动，重构仅限 UI/路由/组件层。
