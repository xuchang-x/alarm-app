# 004 - 闹钟能力扩展调研与需求规格

## 产品定位

基于当前已经具备的四种闹钟、周期调整、本地通知、贪睡和本地 SQLite 能力，规划下一阶段能够提高「安排效率、执行反馈和长期可管理性」的功能，形成可分阶段开发的候选清单。

## 当前能力基线

- 一次、每天、每周、每 N 天四种闹钟类型。
- 本地 SQLite 保存闹钟和周期调整记录。
- 本地通知和通知动作，支持贪睡。
- 列表查看、创建、编辑、删除、启用/暂停。
- 周期闹钟支持跳过一次和临时加一次。
- Expo SDK 56 Managed Workflow，当前不依赖后端。

## 调研方法

按用户价值、与现有模型的贴合度、实现成本、对原生能力的依赖和与核心定位的关系进行评估。候选能力分为 P0（优先验证）、P1（增强管理）、P2（长期能力）。

## 候选能力总览

| 优先级 | 能力 | 用户价值 | 实现成本 | 主要依赖 |
|---|---|---|---|---|
| P0 | 日历/日程视图 | 看清提醒分布和下一次安排 | 中 | 复用调度计算 |
| P0 | 提醒标签与颜色分类 | 快速区分工作、生活、运动等任务 | 低 | 增加轻量字段或本地配置 |
| P0 | 快速复制/从模板创建 | 减少重复录入多个相似闹钟 | 低 | 复用创建参数 |
| P0 | 一次性提醒完成态 | 让过期提醒不再显得像仍在运行 | 低-中 | 明确 occurrence 状态 |
| P1 | 提醒冲突检测 | 避免同一时间多个提醒被忽略 | 中 | 时间范围查询 |
| P1 | 搜索、筛选和排序 | 闹钟变多后仍能快速找到目标 | 低 | 列表查询和 UI 状态 |
| P1 | 批量操作 | 一次暂停、删除或归档多个提醒 | 中 | 多选状态和事务 |
| P1 | 计划预览与未来 7/30 天摘要 | 提前发现排班、浇水和任务密度 | 中 | 复用日历实例计算 |
| P1 | 导入/导出本地备份 | 换设备或重装后恢复数据 | 中 | JSON/文件系统权限 |
| P2 | 自定义铃声和全屏响铃 | 提升提醒到达后的注意力 | 高 | 原生能力，超出 Managed Workflow |
| P2 | 云同步和跨设备 | 多设备共享同一套提醒 | 高 | 后端、账号、冲突合并 |
| P2 | 位置/蓝牙/健康数据触发 | 更智能的情境提醒 | 高 | 后台权限和第三方能力 |

## 推荐开发顺序

### 阶段 1：看得清、建得快

优先开发日历视图、标签分类、快速复制和一次性提醒完成态。

- 日历视图解决「某天有什么」；
- 标签解决「这是什么」；
- 快速复制解决「怎么少填几次」；
- 完成态解决「过期一次性提醒如何理解」。

### 阶段 2：管理变多后的效率

开发冲突检测、搜索筛选排序、批量操作和未来计划摘要。

- 适合闹钟数量从 3~5 个增长到 10 个以上后的场景；
- 不依赖账号和服务端，仍可保持本地优先。

### 阶段 3：提醒基础设施升级

评估导入/导出、自定义铃声、全屏响铃和云同步。

- 导入/导出可先做本地 JSON 备份；
- 自定义铃声和全屏响铃需要重新评估 Expo Managed Workflow；
- 云同步需要先定义账号、隐私和多端冲突策略。

## 优先候选需求详述

### 1. 提醒标签与颜色分类（P0）

- 用户可以给提醒选择预设分类：工作、生活、运动、其他。
- 每个分类带固定颜色和可选图标；卡片、日历和详情页统一展示。
- MVP 使用预设分类，不开放用户自定义颜色，避免主题和可读性失控。
- 需要在 `alarms` 增加 `category` 字段，或使用独立配置表保存分类。

### 2. 快速复制/模板创建（P0）

- 在编辑页和卡片操作中提供「复制」入口。
- 复制保留时间、类型、周期、标签和贪睡设置，但默认不复制一次性日期或调整记录。
- 创建页可从最近使用模板开始，减少排班和重复性提醒的录入成本。
- 模板管理可后置，MVP 先支持「复制当前提醒」。

### 3. 一次性提醒完成态（P0）

- 一次性提醒到达或过期后显示「已完成/已过期」，不再只显示一个无法解释的日期。
- 用户可以重新启用、改日期或删除。
- 需要区分「计划日期已过」和「通知已经实际送达」；MVP 先采用计划日期状态，避免引入通知回执表。
- 卡片和日历历史视图显示完成态，首页默认将完成项折叠到已完成区域。

### 4. 提醒冲突检测（P1）

- 创建或修改提醒时，检测同一日期/时间窗口内是否已有其他启用提醒。
- 默认提示而不阻止保存，用户可以选择继续。
- 周期和每周提醒需要检测未来一段时间，而不是只比较单日。
- 建议初始冲突窗口为同一分钟，后续可扩展为前后 5/10 分钟。

### 5. 搜索、筛选和排序（P1）

- 搜索标签和类型。
- 按启用状态、类型、分类筛选。
- 按下一次响铃时间、创建时间或名称排序。
- 过滤条件在列表和日历之间保持一致；当前筛选状态只保存在本地 UI 偏好中。

### 6. 本地导入/导出（P1）

- 导出 JSON 文件，包含闹钟和周期调整记录，不包含系统通知 ID。
- 导入前预览数量和冲突处理方式：追加、覆盖、跳过重复项。
- 导入失败时不改变已有数据，使用事务回滚。
- 导出的文件需要版本号，方便未来数据模型升级。

## 不纳入近期 MVP 的能力

- 全屏响铃、自定义铃声：需要原生音频/后台能力，不能只靠现有 Expo Managed Workflow 完成。
- 云同步：需要账号、后端、隐私政策和冲突合并，产品规模和风险明显扩大。
- 位置、蓝牙、健康数据触发：需要持续后台权限和额外平台审核，暂不符合当前个人提醒工具定位。
- 社交共享和多人协作：需要权限模型和服务端，不属于当前本地单用户核心场景。

## 数据与技术影响

| 能力 | 是否需要改数据库 | 是否需要通知调度改造 | 是否需要原生能力 |
|---|---:|---:|---:|
| 日历视图 | 否（MVP） | 否 | 否 |
| 标签分类 | 是 | 否 | 否 |
| 快速复制 | 否或少量字段 | 否 | 否 |
| 一次性完成态 | 后续可能需要 | 可能 | 否 |
| 冲突检测 | 否 | 否 | 否 |
| 搜索筛选排序 | 否 | 否 | 否 |
| 导入导出 | 否，但需版本化 | 否 | 文件系统 API |
| 自定义铃声/全屏响铃 | 可能 | 是 | 是 |
| 云同步 | 是 | 是 | 否，但需要后端 |

## 非功能需求

- 保持本地优先，核心提醒在无网络情况下可用。
- 新能力不能破坏现有四类闹钟和周期调整结果。
- 数据迁移必须可回滚，旧版本数据可以继续读取。
- 需要为日期计算、冲突检测、导入导出和完成态补充单元测试。
- 涉及通知、文件和原生权限的功能必须单独评估 iOS/Android 差异。

## 验收标准

1. 文档明确列出当前能力基线和至少 P0/P1/P2 三个优先级层级。
2. 每个候选能力有用户价值、实现成本、数据影响和平台依赖说明。
3. P0 候选可以拆成独立开发任务，不依赖云服务或全屏原生能力。
4. 文档清楚区分近期 MVP、后续增强和暂不纳入范围。
5. 用户选择某个候选方向后，可以继续生成对应的技术设计和任务拆分文档。

## 待确认问题

- P0 是否先做「日历视图 + 一次性完成态」，再做标签和快速复制？
- 标签分类是预设分类，还是允许用户自定义？推荐先预设。
- 一次性提醒的完成态是按计划日期自动完成，还是必须收到通知后才完成？推荐 MVP 按计划日期。
- 导入导出是否需要作为近期能力，还是先不做？
