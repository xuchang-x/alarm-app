# 003 - 闹钟日历视图需求规格

## 产品定位

为现有闹钟列表增加一个日历入口，让用户按月、周、三天、单天查看所有提醒实例，快速理解某一天会有哪些闹钟、周期提醒如何分布，以及某个提醒的下一次响铃时间。

## 需求背景

当前首页以闹钟规则为中心：用户能看到「每天」「每周」「每 N 天」，但不容易回答「这周三有哪些提醒」「本月哪几天会响」「某个周期提醒和一次性提醒是否撞在一起」。日历视图需要复用现有调度计算结果，把规则转换为具体日期和时间。

## 调研结论

参考系统日历、日程类 App 和习惯追踪工具后，推荐采用「月视图看分布、周/三天/单天看时间轴」的组合：

| 视图 | 主要任务 | 推荐交互 |
|---|---|---|
| 月 | 看整月提醒分布和忙闲程度 | 日期格显示数量点/色条，点击日期进入当天详情 |
| 周 | 看一周内的时间安排 | 7 列日期 + 纵向时间轴，点击实例进入编辑 |
| 三天 | 在手机窄屏上比较近期安排 | 3 列日期 + 时间轴，左右切换三天窗口 |
| 单天 | 聚焦当天执行 | 按时间排序的提醒列表，显示状态和操作 |

## 已确认的范围

- 视图必须支持：**月、周、三天、单天**。
- 日历展示现有四种闹钟类型产生的提醒实例：一次、每天、每周、周期。
- 展示开启的闹钟；暂停闹钟默认不参与日历排布，可通过筛选开关查看。
- 周期闹钟的跳过和临时加一次调整必须反映在日历中。
- 点击日历中的提醒实例进入现有编辑页。
- 日历与列表共用同一份本地数据和调度计算逻辑。

## 目标平台

- iOS / Android，继续使用 Expo SDK 56 Managed Workflow。
- MVP 优先适配手机竖屏；平板在同一组件基础上扩大列宽，不单独设计平板布局。

## 功能详述

### 1. 日历入口与视图切换

- 首页增加「列表 / 日历」入口，默认记住用户上次选择的视图。
- 日历顶部显示当前日期范围和返回今天按钮。
- 使用分段控件切换「月」「周」「3天」「日」。
- 左右滑动或左右按钮切换前后日期范围。
- 月视图点击某天后，进入该天详情或将当天选中状态传递给下方详情面板。

### 2. 月视图

- 显示完整月份网格，包含上月末和下月初补位日期。
- 每个日期格显示：
  - 当天提醒数量；
  - 不同提醒类型的颜色点或短色条；
  - 当前日期和选中日期状态。
- 当天有多个提醒时，不在小格内展示完整文案，避免拥挤。
- 点击日期后显示当天提醒列表，按时间升序排列。
- 跨月切换时重新计算可见日期范围，不提前加载无关月份。

### 3. 周视图

- 顶部显示周一至周日和日期。
- 纵向时间轴按小时显示，提醒实例以时间块呈现。
- 同一时间或相近时间的多个提醒需要并列或堆叠，不能互相覆盖导致无法点击。
- 全天区域显示一次性日期提醒或没有具体时间的扩展状态；当前数据模型中所有闹钟都有时间，因此 MVP 可暂不显示独立全天栏。
- 点击时间块进入对应编辑页。

### 4. 三天视图

- 默认展示今天、明天、后天。
- 支持左右滑动，每次移动一天或三天需要在设计阶段确认；推荐每次移动一天以减少错过临近日期的风险。
- 复用周视图时间轴组件，但将列数固定为 3。
- 适合查看周期提醒和近期一次性任务的相邻安排。

### 5. 单天视图

- 顶部显示日期、星期和当天提醒数量。
- 按时间升序显示提醒卡片，复用首页卡片的时间、标签、类型和状态表达。
- 显示已跳过的周期实例时，使用删除线/浅色状态并保留查看入口；默认不把跳过实例当作待执行提醒。
- 当天无提醒时显示空状态，并提供切换日期和创建闹钟入口。

### 6. 筛选与操作

- MVP 提供「只看已开启」开关，默认开启。
- 后续可增加按类型筛选：一次、每天、每周、周期。
- 日历中的实例支持点击编辑；不在日历中直接执行删除，避免误操作。
- 周期闹钟的「跳过一次」「临时加一次」可以在单天详情中提供，但月/周视图只保留查看和编辑入口。

### 7. 实例展示规则

- 一次性闹钟：只在 `onceDate` 对应日期显示；即使日期已过，也可在历史日期查看。
- 每天闹钟：在查询范围内每天生成实例。
- 每周闹钟：只在配置的星期生成实例。
- 周期闹钟：从 `startDate` 按 `intervalDays` 生成，过滤 skip，合并 add。
- 同一闹钟的实例需要携带闹钟 ID 和实例日期，点击后进入现有编辑页并保留上下文日期。

## 数据存储

### MVP

不新增数据库表和字段。使用现有 `computeRingDatesInRange` 查询指定日期范围的实例，并读取 `alarm_adjustments` 反映跳过和临时加一次。

### 后续

如果需要记录「已完成」「已读」「实际响铃结果」等事件，再新增 `alarm_occurrences` 或 `alarm_history` 表；本需求 MVP 不引入该状态，避免把计划实例和执行结果混在一起。

## 非功能需求

- 月视图一次最多计算约 42 天，周视图 7 天，三天视图 3 天，单天视图 1 天；切换视图不阻塞主线程。
- 日历实例必须与通知调度使用同一套日期计算规则，不能出现日历显示和通知触发不一致。
- 日期计算使用设备本地时区；跨夏令时地区需要以本地日历日为准，不能用固定毫秒差判断日期。
- 视图切换和前后翻页保留滚动位置策略，避免用户每次回到顶部后丢失上下文。
- 小屏设备上月视图日期格可点击区域、时间轴实例可点击区域满足可操作尺寸。
- 加载中、查询失败、无提醒三种状态都有明确反馈。

## 验收标准

1. 用户可以在列表和日历之间切换，并在月、周、三天、单天四种视图之间切换。
2. 月视图能正确显示当前月份内各日期的提醒数量和类型提示。
3. 周、三天、单天视图能按时间顺序显示一次、每天、每周、周期四类提醒实例。
4. 周期闹钟的 skip 和 add 调整能正确反映在对应日期中。
5. 点击任意实例可以进入现有编辑页；日历显示的实例日期与调度计算结果一致。
6. 默认只展示已开启闹钟，用户可以切换查看暂停闹钟。
7. 跨月、跨周和切换回今天后，日期范围和实例数据正确更新。
8. 无提醒、加载中和查询失败状态可理解且可恢复。
9. 不修改现有通知调度规则；现有调度和日期测试继续通过。

## 待确认问题

- 三天视图左右滑动是移动一天还是移动三天？推荐移动一天。
- 周视图默认周一开始还是跟随系统地区？推荐跟随当前产品约定的周一开始。
- 月视图点击日期后，是展开当天详情还是跳转单天视图？推荐在月视图下方展开详情，减少页面跳转。
- 是否需要在日历中展示暂停闹钟？推荐默认隐藏，通过筛选开关显示。
