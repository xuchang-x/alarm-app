# 002 - 闹钟 UI 视觉与交互优化需求规格

## 产品定位

在保留现有闹钟能力的基础上，重做首页列表、创建/编辑表单和周期闹钟信息呈现，让用户能更快看懂「什么时候响、为什么响、下一次什么时候响」，同时建立一套统一、可扩展的视觉规范。

## 调研范围

本次只采用有公开源码仓库和明确许可证的设计系统作为视觉参考，详细来源见 [research.md](research.md)。原型中的视觉是结合本项目需求重新组合，不直接复制第三方页面。第 1~9、13 套适合直接作为 Expo React Native 的候选，第 10~12、14~15 套用于跨端视觉参考。

已纳入原型的 15 套方向：

1. **Material 3 / React Native Paper（MIT）**：深色表面、紫蓝主色、分段控件、卡片和 FAB。
2. **Eva / UI Kitten（MIT）**：浅色暖灰底、圆角大卡片、状态色和主题 token。
3. **Tamagui（MIT）**：中性黑白底、青绿色强调、紧凑信息层级和 token 驱动。
4. **gluestack-ui（MIT）**：浅灰背景、白色浮层、胶囊控件和轻阴影。
5. **React Native UI Lib（MIT）**：深海军蓝、青色强调、时间线和效率工具信息密度。
6. **RNEUI（MIT）**：浅蓝面板、橙色主操作和效率卡片。
7. **Fluent UI React Native（MIT）**：中性灰阶、蓝色状态和规整面板。
8. **Ant Design React Native（MIT）**：暖白底、红色主按钮和清晰表单分组。
9. **NativeWind（MIT）**：石墨黑底、荧光绿和紧凑工具感。
10. **Ionic Framework（MIT）**：靛蓝背景、圆润浮层和移动导航感。
11. **Framework7（MIT）**：深蓝列表、红色强调和高信息密度。
12. **Onsen UI（Apache-2.0）**：白底细线、青绿色和轻量交互。
13. **NativeBase（MIT）**：炭黑表面、琥珀色和层级卡片。
14. **Chakra UI（MIT）**：淡紫背景、粉色主色和超大圆角。
15. **Radix Themes（MIT）**：白底细边框、紫色强调和无障碍优先。

## 目标平台

- iOS / Android，继续使用 Expo SDK 56 Managed Workflow。
- 本需求只调整 UI 层和交互组织，不改变本地通知、SQLite 数据模型和周期计算逻辑。
- 首次实现以选定的一套视觉方案为主，颜色和间距使用 token 方便后续扩展。

## 功能详述

### 1. 首页列表

- 顶部显示页面标题和当前开启的闹钟数量。
- 闹钟按「已开启」「已暂停」分组，或按最近一次响铃时间排序，具体方案由视觉方向确认后确定。
- 卡片显示：时间、标签、重复规则、下次响铃日期（周期/一次性闹钟）、开关。
- 点击卡片进入编辑；点击开关直接切换启用状态。
- 周期闹钟保留左滑操作：跳过一次、临时加一次、删除；时间线方向可在卡片上直接显示快捷操作。
- 空状态显示解释文案和主按钮「创建第一个闹钟」。
- 右下角悬浮按钮或底部主按钮保留为快捷入口，具体取决于选定方案。

### 2. 创建/编辑页面

- 顶部展示大号时间和页面标题，保存按钮固定在导航栏或底部安全区。
- 重复方式使用分段控件或胶囊选择：一次、每天、每周、周期。
- 只展示当前重复方式需要的字段：一次显示日期，每周显示星期选择器，周期显示间隔天数和起始日期。
- 标签输入使用明确的占位文案和字数限制提示。
- 贪睡时长使用步进器或紧凑数字输入，默认值保持 10 分钟。
- 表单分为「时间与重复」「提醒信息」「高级设置」三组，降低长页面的阅读负担。
- 保存失败时保留输入内容并给出就地错误提示。

### 3. 页面状态原型

- 原型需逐套展示四种状态：首页列表、创建闹钟、编辑闹钟、空状态。
- 编辑页显示已有闹钟数据、保存修改和删除入口。
- 空状态显示说明文案和「创建第一个闹钟」入口，可跳转到创建页。

### 4. 视觉系统

- 建立颜色、间距、圆角、字体层级 token，组件不再直接散落颜色值。
- 深色主题的背景与卡片保持明显层级；浅色主题使用足够的边框/阴影保证可读性。
- 主时间使用最大字号，重复规则和下次日期使用次级字号，辅助动作使用按钮色块或图标区分。
- 开关、分段控件、日期按钮、星期选择器在选中/禁用/按下状态下均有明显反馈。
- 页面在小屏设备上不出现横向溢出，底部操作避开安全区。

## 数据存储

不新增数据表和字段。继续使用现有 `alarms`、`alarm_adjustments` 表及本地 SQLite 存储。UI 仅消费现有闹钟类型、启用状态、标签、周期参数和下次响铃计算结果。

## 非功能需求

- 不改变通知调度和周期计算行为。
- Expo SDK 56 Managed Workflow 可直接运行，不引入需要原生编译的新依赖。
- TypeScript strict，组件保持函数式写法，样式统一使用 `StyleSheet.create`。
- 首页首屏在本地数据加载完成后保持流畅，列表滚动无明显掉帧。
- 交互命中区域不小于系统推荐的可操作尺寸，开关和快捷操作可被辅助技术识别。

## 验收标准

1. 15 套方案在原型中均能查看首页列表、创建闹钟、编辑闹钟和空状态，并标注开源来源与许可证。
2. 首页能清楚区分已开启和已暂停闹钟，卡片主时间、标签、重复规则、下次日期层级明确。
3. 周期闹钟在首页直接显示「每 N 天」和下一次日期，并保留跳过/加一次/删除快捷操作。
4. 创建和编辑页面在一次、每天、每周、周期之间切换时，只展示对应设置项，输入内容不会异常丢失。
5. 开关、分段控件、星期选择器、日期按钮和保存按钮均有选中、按下、禁用反馈。
6. 空状态、加载状态、保存失败状态均有可理解的文案和恢复路径。
7. 不修改现有通知触发、数据库读写和周期计算结果；现有相关测试继续通过。
8. 产品确认其中一套方向后，再进入技术设计和任务拆分。

- 首页默认按「已开启 / 已暂停」分组，还是按最近响铃时间排序？
- 周期快捷操作是否保留左滑，还是改为卡片上的显式按钮？
- 标签是否需要预设图标/颜色分类，还是先保持纯文本？
