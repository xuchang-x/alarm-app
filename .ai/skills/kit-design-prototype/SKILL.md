# 原型设计 (Prototype Design)

当需求文档确定后，按照以下流程进行原型设计，最终输出可交互的 HTML 原型文件，供后续 AI 开发使用。

## 触发条件

需求文档（`.ai/specs/{NNN}-{feature-name}/requirements.md`）已完成，用户希望在编码前先确认交互和视觉方案。

## 执行流程

### 第一步：业界调研

围绕需求文档中的功能点，调研业界同类产品的交互方案：

- 同类 App 的核心交互模式（如列表展示、创建流程、操作手势）
- 各方案的优劣对比
- 适合本项目的推荐方案

调研结果简要展示给用户，不需要输出独立文档。

### 第二步：设计方向确认

基于调研结果，向用户逐一确认关键设计决策（使用结构化问答）：

**视觉风格**
- 整体色调（深色 / 浅色 / 跟随系统）
- 设计语言倾向（iOS 原生风 / Material Design / 自定义）

**核心交互**
- 页面结构（Tab 导航 / 单页列表 / 抽屉）
- 创建/编辑流程（新页面 / 弹窗 / 内联展开）
- 关键控件选择（如时间选择器样式、选项选择方式）

**操作方式**
- 快捷操作（左滑 / 长按 / 按钮）
- 列表排序和分组方式

一次提问不超过 5 个问题。根据需求复杂度可分 2-3 轮确认。

### 第三步：确认页面清单

列出所有需要设计的页面/状态，让用户确认：

- 哪些页面是必须的
- 是否有遗漏的状态（如空状态、错误状态、加载状态）
- 页面优先级排序

### 第四步：生成原型

技术方案：**单文件 HTML**（Tailwind CSS + Alpine.js），包裹在手机外框内模拟真机效果。

**原型要求：**
- 所有确认的页面/状态都包含在一个 HTML 文件中
- 底部或顶部提供页面切换导航（仅原型用，非最终产品设计）
- 交互可操作：按钮点击、开关切换、选项选择等应有视觉反馈
- 动态联动：如选择不同类型后展示不同设置项
- 使用 CDN 引入依赖（Tailwind CSS CDN、Alpine.js CDN）

**输出路径：** `.ai/specs/{NNN}-{feature-name}/prototype/index.html`

### 第五步：Review 与迭代

在浏览器中打开原型，请用户查看并反馈：

- 逐页确认交互是否符合预期
- 收集修改意见，迭代调整
- 重复直到用户确认通过

## 注意事项

- 原型是用于确认交互方案的工具，不是最终 UI —— 追求「能说清楚交互」即可，不必像素级完美
- 设计决策应基于需求文档，不要引入需求文档中没有的功能
- 用户如果对某个设计点没有明确偏好，给出推荐方案并说明理由
- 深色主题下注意对比度，确保文字可读
- 原型文件应自包含，用浏览器直接打开即可预览，不需要额外构建步骤
- 关闭/禁用状态用文字颜色变暗表达，不要用整体 opacity（会导致层叠元素透出）
