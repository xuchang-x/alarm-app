# 打 APK 与签名：Expo 项目的构建机制科普

> 2026-10-04 记录。回答四个问题：怎么打 APK、签名是啥、为什么只开 android 目录、JS 代码怎么进 APK 的（以及为什么构建前不需要 prebuild）。

## 一、怎么打 APK

### 方式一：Android Studio 图形界面

1. 用 Android Studio 打开项目下的 **`android/` 目录本身**（不是项目根目录，原因见第三节）
2. 等 Gradle Sync 完成
3. 菜单 **Build → Build App Bundle(s) / APK(s) → Build APK(s)**
4. 构建完右下角弹通知，点 **locate** 跳到产物目录

产物路径：

- Debug：`android/app/build/outputs/apk/debug/app-debug.apk`
- Release：`android/app/build/outputs/apk/release/app-release.apk`（未签名时是 `app-release-unsigned.apk`，装不上手机）

### 方式二：命令行（脚本化 / CI 友好）

```bash
cd android/

# 本机必须先设这两个环境变量（系统默认 JDK 24 会让 CMake 报 restricted method 错）
export JAVA_HOME=/Users/xuchang09/Library/Java/JavaVirtualMachines/ms-17.0.16/Contents/Home
export CMAKE_VERSION=3.31.1

./gradlew assembleDebug    # Debug 包
./gradlew assembleRelease  # Release 包
```

### Release 包的签名问题

- Debug 包自动用 SDK 自带的 debug keystore（`~/.android/debug.keystore`），直接能装
- Release 包默认不签名，**必须配了签名才能安装**

临时方案（自己测试）：在 `android/app/build.gradle` 让 release 用 debug 签名：

```gradle
android {
    buildTypes {
        release {
            signingConfig = signingConfigs.debug
            minifyEnabled false  // 先关掉，避免混淆配置问题
        }
    }
}
```

正式方案：生成自己的 keystore 并配置 `signingConfigs`：

```bash
keytool -genkeypair -v -storetype PKCS12 \
  -keystore android/app/alarm-release.keystore \
  -alias alarm-key -keyalg RSA -keysize 2048 -validity 10000
```

keystore 和密码不要提交进 git（放 `gradle.properties` 或环境变量）。

## 二、签名是啥

一句话：**给 APK 盖一个"开发者公章"，证明这个包是你打的、且没被人篡改过。**

安卓系统硬性规定：**没有有效签名的 APK 拒绝安装**，这就是 `app-release-unsigned.apk` 装不上的原因。

它解决两个问题：

1. **身份认证** —— 系统通过签名识别应用是谁发布的。覆盖升级（v1.0 → v1.1）要求前后两次用同一个签名，否则必须先卸载重装。
2. **完整性校验** —— APK 里每个文件都参与签名计算，传输中被改过一个字节，签名校验就失败。

原理是非对称加密：

- 生成一对密钥：**私钥**（keystore 文件，打死不能丢不能泄露）+ **公钥**（证书，随 APK 分发）
- 打包时用私钥对内容算签名写进包里；安装时系统用公钥验证

对项目的实际影响：

- 自己装自己手机测闹钟 → debug 签名的 release 包（甚至直接 debug 包）就够
- 给别人装 / 上架 → 必须用正式 keystore，**且从第一个正式版本起固定用同一把**——丢了密钥就永远无法覆盖升级，只能换包名重新上架

## 三、为什么 Android Studio 要开 android/ 目录

项目结构决定的：

```
alarm-app/               ← Expo 的 JS 工程根（VS Code 开这边写代码）
├── app.json             ← Expo 配置
├── package.json         ← JS 依赖
├── src/                 ← TS/React 业务代码
└── android/             ← expo prebuild 生成的完整安卓原生工程
    ├── build.gradle     ← Gradle 工程入口
    ├── settings.gradle
    └── app/
```

Android Studio 只认 Gradle 工程结构，看不懂 `package.json`。`android/` 才是一个自洽的、可独立打开构建的 Gradle 项目。

但日常开发**不是每次都要开 Android Studio**：

- 改 JS 代码 → 终端 `npx expo start --dev-client` 配合已装的 dev build，热更新
- 只打 APK → 命令行 `./gradlew` 就够
- Android Studio 不可替代的场景：看 Logcat 排查原生日志（通知调度日志）、断点调原生代码、Profile 性能

## 四、JS 代码怎么进 APK 的

**不是拷贝进 android 目录，而是构建时打成一个 bundle 塞进 APK。**

Release 构建时 Gradle 执行 `bundleReleaseJsAndAssets` 任务：

```
src/**/*.tsx, app.json, node_modules ...
        │
        ▼  Metro 打包（编译 TS、打包 JS、处理资源）
android/app/build/generated/assets/.../index.android.bundle
        │
        ▼  作为资源打进 APK
app-release.apk
```

要点：

- android 目录平时看不到业务代码，JS 只在构建时被打成 `index.android.bundle` 塞进去（类似 webpack dist）
- 打 bundle 不是 Android Studio 的功能，是 **Gradle 任务 fork 一个 Node 进程去调 Metro**
- **Debug 和 Release 的代码来源不同**：
  - Debug：bundle 不打进 APK，dev client 启动时从电脑上的 Metro dev server 实时加载——所以改代码能热更新
  - Release：bundle 完整打进 APK，装到手机后完全离线运行

### 只开 android 目录，怎么拿到上层的 JS 代码？

`android/settings.gradle` 里的路径写死了指向上层：

```gradle
apply from: new File(["node", "--print", "require.resolve('expo/package.json')"]
    .execute(null, new File("..", "install")).text, "../scripts/autolinking.gradle");
```

那个 `new File("..", ...)` 就是项目根 `alarm-app/`。链路：Gradle 读 android 配置 → autolinking 从 `../node_modules` 把 RN/Expo 原生依赖链接进工程 → Metro 以项目根为工作目录打 JS bundle。所以 `node_modules` 必须是装好的，其余不需要任何额外步骤。

## 五、构建前不需要 prebuild（重要）

**prebuild 是"生成工具"，不是"构建步骤"。** android 目录已是实体工程，Gradle 打 APK 只看这个目录，不会去问 Expo 要配置。

| 场景 | 要不要 prebuild |
|------|----------------|
| 日常打 APK | ❌ 不用 |
| 改了 JS 代码重新打包 | ❌ 不用 |
| `app.json` 里改了映射到原生的配置（权限、图标、包名、plugin 参数） | ✅ 要 |
| 新装了带原生代码的依赖 | ✅ 要（跑一次让依赖接进原生工程） |
| Expo SDK 升级 | ✅ 要 |

**本项目的坑**：通知功能做过原生层处理，prebuild 是"按 app.json 重新生成 android 目录"，手动改过的 `AndroidManifest.xml`、`MainActivity` 会被冲掉（除非把手法治写成 config plugin）。

正确姿势：

- 把 `android/` 当正常安卓工程做 git 管理（提交、看 diff）
- 原生配置变更**优先直接改 android 目录里的文件**，而不是改 app.json 再 prebuild
- 真要跑 prebuild（装新原生依赖 / 升 SDK）前先 `git status` 确认干净，万一覆盖可 `git checkout` 找回

## 六、日常工作流总结

```
VS Code（项目根）改 TS 代码
    │
    ├─ 日常调试: npx expo start --dev-client + 已装 dev build（热更新）
    │
    └─ 打包测真实通知: Android Studio（开 android/）点 Build APK
       或命令行 ./gradlew assembleDebug / assembleRelease
       （命令行记得先 export JAVA_HOME 和 CMAKE_VERSION）
    │
    ▼
新 APK 装真机验证（Expo Go 里闹钟通知是静默降级的，必须 dev build / release 包才能测）
```

注意：本地 release 包不存在"只更新 JS 不重打 APK"的捷径（应用商店 OTA 是另一回事，闹钟这类强通知调度的 app 上要谨慎用）。
