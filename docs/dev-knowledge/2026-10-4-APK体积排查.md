# APK 体积排查：为什么 101MB

> 2026-10-04 记录。0.1.0 首次打 release APK 后发现体积 101MB，本文记录排查过程、体积构成结论、以及各优化方案的性价比。配合 [打APK与签名](./2026-10-4-打APK与签名.md) 阅读。

## 一、怎么排查的

一条命令按大小列出 APK 内容，直接看大头在哪：

```bash
unzip -l android/app/build/outputs/apk/release/app-release.apk | sort -rn -k1 | head -20
```

再按目录分组统计（lib 按 ABI 分、dex 合计），得到构成。

## 二、体积构成（0.1.0 实测，未压缩 138MB / 压缩后 101MB）

| 构成 | 体积 | 说明 |
|------|------|------|
| 全 ABI 原生库 `.so` | ~75MB | **最大头**。arm64 + armeabi-v7a + x86 + x86_64 四套架构全打进去了，其中 x86/x86_64 约 41MB 只给模拟器用，真机完全用不到 |
| dex 字节码（5 个 classes.dex） | ~48MB | JS bundle 转译 + expo 全家桶依赖的类。autolinking 按已安装依赖全量打入，不裁剪的 Expo 项目正常水位 |
| JS bundle（index.android.bundle） | ~3.7MB | 业务代码本身很小，不是问题 |
| resources.arsc + res 资源 | ~5MB | 图标等，可忽略 |

**结论：业务代码占比极小，体积大是「全 ABI + 全量依赖」的架构性开销，不是代码写胖了。**

## 三、优化方案对比（按性价比排）

### 方案一：只打 arm（首选，101MB → 约 60MB）

真机几乎全是 arm；x86 两套纯粹是给模拟器用的。在 `android/app/build.gradle` 的 release 变体里限定 ABI：

```gradle
android {
  buildTypes {
    release {
      ndk {
        abiFilters "arm64-v8a", "armeabi-v7a"   // 兼容老机器；只留 arm64 再小 ~8MB
      }
    }
  }
}
```

注意：**debug 变体不要限**，否则模拟器（x86_64）装不上。缺点是 universal APK 装到 x86 设备会闪退——本 App 只有自己用，无此顾虑。

### 方案二：AAB 分发（再砍一半，但有前提）

`./gradlew bundleRelease` 出 `.aab`，走 Play 商店分发时**商店按设备下发单架构的库**，用户到手通常只有 30~40MB。不上商店（自用/直发 APK）用不上，AAB 本身不能直接安装。

### 方案三：r8/proguard 收缩 dex（收益小、风险大）

release 开 `minifyEnabled true` 能剪掉没用到的依赖类。但 RN/Expo 项目 shrink 规则容易踩坑（反射调用的类被误剪、运行时才炸），Hermes 引擎下 JS 侧不受影响、只能剪原生层，**收益几 MB 级别，不建议为这点体积引入排查成本**。

## 四、决策

自用场景采用方案一即可：release 限 arm 双架构，预期 ~60MB，真机功能零影响。等将来真要上商店，直接切 AAB（方案二），ABI 交给商店处理。

## 五、附带经验：prebuild 与版本号漂移

排查体积时顺带确认的一个坑：`android/app/build.gradle` 的 `versionCode/versionName` **不跟** package.json / app.json 的 bump 流程走，它只在 `npx expo prebuild` 时从 app.json 重新生成。本仓库的迭代流程只 bump 两处，所以 build.gradle 会长期停留在上次 prebuild 时的版本号（本次发现停在 0.0.5）。

重新 prebuild 的完整姿势（**会冲掉手工改动，必须备份**）：

1. 备份三个手工改过的文件：`res/values/styles.xml`（MaterialCalendar 皮肤主题）、`res/values/colors.xml`（skin_* 镜像色）、`MainActivity.kt`（zh-CN locale）
2. `npx expo prebuild -p android --no-install` —— versionName 刷成 app.json 的值，但 **versionCode 会被重置为 1**，需手动改成递增值（本次 0.1.0 → versionCode 4）
3. 恢复三个备份文件
4. 重新 `./gradlew assembleRelease`

alarm-ring 本地模块不受 prebuild 影响（走 autolinking，manifest/res 都在模块目录里）。
