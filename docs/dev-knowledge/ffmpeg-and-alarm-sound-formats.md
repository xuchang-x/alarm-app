# FFmpeg 是什么，闹钟铃声的格式与音源从哪来

007 提示音迭代里冒出了一堆名词：FFmpeg、OGG、WAV、M4R、-1dB 归一化……这篇文档把这些概念一次性讲清楚，不预设你有音频背景。读完你应该能明白：为什么内置提示音选 OGG、为什么 iOS 通知音只能 30 秒、FFmpeg 在整个流程里干的是哪件活、以及那些提示音文件到底从哪下载来的。

## 一、先说 FFmpeg：音频世界的「万能转换插头」

一句话：FFmpeg 是一个开源的音视频处理工具包，几乎能干任何和音视频文件相关的活——转格式、剪片段、调音量、改采样率、抽音频、压体积。它是命令行工具（没有图形界面），长这样：

```bash
ffmpeg -i 源文件.mp3 -c:a libvorbis -b:a 96k -filter:a loudnorm 目标文件.ogg
```

拆开看就是：`-i` 指定输入文件，中间一堆参数告诉它怎么处理，最后是输出文件名。文件后缀（.ogg）本身就是给 FFmpeg 的指令之一——它根据后缀决定输出成什么格式。

为什么专业做音频的人都绕不开它？因为各大平台对音频格式的要求五花八门（下一节会看到 Android 偏好 OGG、iOS 通知只认几种格式），而 FFmpeg 一个工具就能把同一份源文件「浇铸」成任何目标格式，且转换质量和可控性远超在线转换网站。Spotify、YouTube、 VLC 播放器的底层都有它的身影。

### 它在我们项目里干三件事

007 的设计里，从渠道下载的音源是「原材料」（可能是 MP3、WAV、44.1k 或 48k 采样率、响度大小不一），FFmpeg 负责统一加工成「成品」：

1. **统一转 OGG**：Android 模块 `res/raw/` 里放的是 OGG 文件，源文件是什么格式无所谓，转就完了。
2. **响度归一化到 -1dB**：不同渠道下载的音源，有的录得响、有的录得轻。不处理的话，用户切铃声会发现「这个铃声炸耳、那个听不见」。统一做峰值归一化，把所有文件的峰值对齐到 -1dB（留 1dB 余量防削波失真），切哪个都一样响。
3. **采样率统一到 44.1kHz**：采样率可以理解为声音的「分辨率」。Android 官方建议 44.1kHz，从 48k 降到 44.1k 不会产生低通副作用，所以全按 44.1k 加工。

## 二、闹钟/铃声世界常用哪些格式，为什么

先补两个基础概念，后面就好懂了：

- **无压缩 vs 有压缩**：WAV 是把声音波形原样存下来，体积大但 quality 无损；MP3/OGG 这类是「有损压缩」，扔掉人耳不太敏感的细节，体积小一个数量级。当铃声这种场景，有损压缩的音质完全够用。
- **容器 vs 编码**：平时说的「格式」多数指文件后缀（容器），里面装的才是真正的编码。比如 M4R 文件里装的是 AAC 编码，OGG 文件里装的是 Vorbis 编码。

### 各平台的惯例一览

| 格式 | 压缩方式 | 谁在用 | 关键约束 |
|---|---|---|---|
| OGG Vorbis | 有损、开源免费 | Android 系统铃声/闹钟的标准格式（AOSP 惯例） | 无；支持 LOOP 元数据（循环点写在文件头，无缝循环） |
| WAV | 无压缩 | 通用兜底格式；expo-notifications 官方推荐 | 体积大（30 秒约 5MB），不适合大量打包 |
| MP3 | 有损、专利已过期 | 用户本地音乐的事实标准 | 无循环元数据，接缝可能有杂音 |
| M4R (AAC) | 有损 | iOS 来电铃声专用 | **来电 40s 上限；通知音 30s 上限且只播一次** |
| CAF | 容器格式 | iOS 通知音（打包进 App） | 苹果生态专用 |
| FLAC | 无损压缩 | 音乐发烧友的本地音乐 | 当铃声纯属浪费体积 |

几个「为什么」值得单独说：

**为什么 Android 偏爱 OGG？** 开源免费是一方面，更实用的是 OGG 的文件头可以写 LOOP 元数据——系统播放器读到后会自动在指定点位循环，闹钟短音（比如 2 秒的蜂鸣）就能无缝循环响下去而听不出接缝。MP3 没这个能力。

**为什么 iOS 限制这么多？** 苹果对通知/铃声走的是「打包进 App + 系统统一调度」路线，通知音 30 秒上限且只播一次是系统硬性规定，不是技术做不到。这也是本项目响铃要走 Android 原生 RingService 自己循环、而不是依赖通知层的历史原因之一（详见 [alarm-ring-duration-research.md](./alarm-ring-duration-research.md)）。

**为什么本项目打包 OGG + WAV 双份？** OGG 给 alarm-ring 模块的 RingService 播放（体积小，是主力）；WAV 是给 expo-notifications 插件的 sounds 数组备的（它官方推荐 .wav），属于 iOS/Expo Go 降级路径的双保险。

**用户选本地音乐为什么不限格式？** 响铃由 Android 原生 MediaPlayer 承载，它支持 MP3/M4A/OGG/FLAC/WAV 等所有主流格式，所以选什么歌就能放什么歌，格式跟随源文件。

## 三、提示音文件从哪来：渠道与版权

「从哪来」有两层意思：渠道上从哪下载，法律上能不能用。

### 可用渠道

| 渠道 | 许可证 | 特点 |
|---|---|---|
| Pixabay Sound Effects | Pixabay 许可（≈CC0，可商用免署名） | **首选**，量大，直接下载 |
| Mixkit | 免费商用无需署名 | 分类细（alarm/UI/notification），MP3/WAV 都有 |
| Freepd | CC0 | 公共领域音乐 |
| Sonniss GDC | 免费商用无需署名 | 游戏音效大包，质量高 |
| AOSP 开源铃声 | Apache 2.0 | Android 系统自带铃声的源码，可直接复用（如经典双铃闹钟） |

「CC0」意思是作者主动放弃所有权利，进入公共领域，商用、修改、打包进 App 都随便，不用署名。Pixabay 许可基本等同 CC0。Apache 2.0 是宽松的开源协议，附一份许可声明即可。

### 避坑记录

- **Zedge 不用**：UGC 平台，铃声是用户上传的，版权混杂，商用内置音源风险不可控。
- **Freesound 只挑 CC0 项**：站内一部分素材是 CC BY-NC（禁止商用），混着来，必须逐个看许可证。

本项目最终入选的 10 个音全部来自上述安全渠道，具体清单见 [alarm-sound-research.md](./alarm-sound-research.md) 第三部分。

## 四、串起来看整个流程

1. 从 Pixabay/Mixkit/AOSP 下载音源（可能是 MP3/WAV，格式、响度、采样率参差）
2. FFmpeg 统一加工：转 OGG + 响度归一化 -1dB + 采样率 44.1kHz
3. 成品放进 `modules/alarm-ring/android/src/main/res/raw/`（命名加 `ars_` 前缀防冲突）
4. 响铃时 RingService 读资源播放，循环够 30 秒自停；用户本地音乐则走 MediaPlayer 直播源文件
