# 0.0.4（开发中）

发布日期：待发布

## 功能迭代

### 1. 提醒响铃循环播放够 30 秒

提醒从「一声系统提示音」升级为真闹钟语义，响铃由自研原生模块（modules/alarm-ring）承载：

- 循环播放直至满 30 秒：短铃声循环补齐、长铃声截断，时长是常量可配（改 50s 只改一处）
- 调度可靠性升级：响铃计划持久化到原生层，App 被杀、设备重启（BootReceiver 重排）均不丢；四类闹钟统一由链式精确闹钟触发
- 响铃通知带「关闭 / 稍后提醒」按钮，贪睡由原生直接重排
- 平台分层：Android 走原生模块；iOS / Expo Go 降级走原通知路径，上层调用语义不变

### 2. 通知调度可靠性加固

提醒「到不到点」的底层保障全面加固，修复两个高危问题：

- 调度上限防护：once/cycle 批量预调度按单闹钟 60 条截断，不再超出 iOS 系统 64 条上限后被静默丢弃；截断的后续日期由「回前台补排」自动续期
- 落库/调度一致性：通知调度失败不再误报「创建失败」（数据已保存），改为如实提示「提醒已保存，通知调度失败」，避免重试产生重复数据
- 回前台自动维护：App 从后台切回时自动关闭过期一次性闹钟并补排调度，兜住设备重启/系统清理调度通知的场景
- 冷启动容错：初始化流程全链路 try/catch，数据库初始化失败不再白屏无提示

### 2. 通知交互行为修正

- 点击通知正文跳转编辑页不再同时静默关闭一次性闹钟（查看 ≠ 关闭）；「关闭」按钮行为不变
- 响完未处理的一次性闹钟自动归位关闭态，列表不再显示误导性的「已开启」

### 3. 交互操作防护

- 滑动删除补二次确认，与编辑页删除入口行为一致
- 编辑页取消时若有未保存改动先确认再退出
- 开关切换/删除/复制/跳过等异步操作失败时给出错误提示，不再静默失败
- 一次性闹钟日期选择不再允许选过去日期（含编辑态）

## 工程与平台迭代

### 1. 自研本地 Expo 模块 alarm-ring

首个本地原生模块落地（Kotlin，可提交进仓库，autolinking 自动编译）：AlarmManager 精确触发 + 前台服务 MediaPlayer（USAGE_ALARM + isLooping），Android 12+ 精确闹钟权限降级、Android 14+ 前台服务类型声明均已处理；配套 ring-scheduler 平台分发层 5 个测试（原生路径/降级路径/时长传递），全量 76 测试通过，assembleDebug 构建验证通过。

### 2. 竞态与数据一致性修复

- 闹钟开关改为原子置位（读库后按目标值写入），快速连点不再出现开关状态与通知调度不一致
- 列表「下次响铃」异步加载加取消守卫，闹钟快速变化时旧请求不再覆盖新状态

### 3. 通知调度测试覆盖

notification 服务从零测试到 9 个用例，覆盖调度上限截断、部分失败容错、旧通知取消、skip 调整生效等关键路径（jest mock expo-notifications 桩方案）。

## 文档与规范迭代

### 1. 响铃时长与提示音调研沉淀

- 响铃时长调研：为什么纯通知层做不到循环 30 秒（Android 渠道声音无法循环、iOS 通知音只播一次），以及原生闹钟模块的架构决策
- 提示音调研：业界格式惯例（Android OGG / iOS WAV+30s 上限）、免版权音源渠道（Pixabay / Mixkit / AOSP）、20 个候选提示音清单与建议入选的 10 个，为下迭代内置提示音 + 本地音乐铃声铺路
- 编辑闹钟后历史与未来行为边界：真实响铃不变、日历显示随新规则重算的取舍说明
